## Open

1. **Playoff seeding tiebreaks** — `LeagueOperations.ranked_team_ids()` sorts on wins desc, losses asc and breaks ties by slug, i.e. alphabetically. That order now seeds a visible bracket (and has always set the draft order), so an alphabetical tiebreak is a user-facing wrong answer. Goal differential is available from `games`; the fix belongs in the record sink / standings, and both callers pick it up for free.
2. **Contract terms for the pre-existing roster** — players imported before contracts were modelled may sit on `years_remaining` values that don't reflect an intended deal; a commissioner tool to (re)assign term/value in bulk would avoid a rollover dumping half the league into free agency. The per-player mechanism exists (`Player.update_contract` → `salary_cap.validate_contract`); this is the bulk/admin path.
3. **Roster-legality season-start check** — `season_readiness` now carries two checks (hard cap, free agency open). A team that can't field a legal lineup (short a position after retirements/expiries, or holding unplaced signings) should be a blocker too; the registry takes a new check without any API or UI change.
4. **Free-agency polish, once it has been run for real** — an auto-forfeit clock (there is no timer; the only remedy for a stalling manager is a commissioner force-forfeit, with `waiting_since` shown on the board), and a public "who bid what" view of a closed round (the revealed offers are in `fa_offers`, but only the live boards are surfaced today).

## Done

- **Playoffs** — `handball/playoffs.py` over alembic `0012`'s `playoff_series`, with the bracket's pure shape (seed, pair, name a round) staying in `handball/postseason.py` so the in-memory `PlayoffService` and the persisted one cannot disagree about what a bracket is. Top 8 per conference, ONE game per matchup, higher seed hosts and advances on a tie; quarterfinals → semifinals → conference final → a cross-conference Final. 15 games.
  - **A round per click.** `POST /playoffs/rounds/run` is a background job on the same run slot as a period (`season_state.run_kind` says which phase owns it, because `reset_run` rolls back by WEEK RANGE and would delete real games if it mistook one for the other). The next round's matchups are materialized the moment a round finishes, so managers see who they play and can fix a lineup before it is run.
  - **Re-seeded, not a fixed ladder** — survivors are re-paired best-vs-worst each round on their ORIGINAL conference seed, so a 4-seed that upsets the 1 is still the 4. The Final is hosted by the better regular-season record: both conference champions are usually 1-seeds, so the seed cannot break that tie, and `teams` W-L still holds the finished season because nothing in the postseason writes to it.
  - **What a playoff game does not touch is the point.** Games are played on team copies loaded fresh and never saved (the trick the in-memory service already used), so W-L, the draft order, and the bracket's own seeding stay exactly as the regular season left them. What it does write: `games` + `player_game_lines` flagged `is_playoff`, so box scores and playoff stat lines exist while `player_season_stats` / `player_leaderboard` (recreated in 0012) and `offseason._top_player` see regular-season lines only — an award is for the season, and counting the postseason would hand every one of them to whoever went deepest.
  - **Injuries** carry over and tick per round, treating a round as a chunk (`PERIODS + round`) — but only for the teams that PLAYED it. An eliminated team's injuries carry to the offseason exactly as they would have if the playoffs had not happened.
  - `POST /playoffs/{start,rounds/run,reset}` are commissioner-only; `GET /playoffs/bracket` is the one document the Playoffs page renders and polls. `/season/advance` now waits for a champion, since the rollover zeroes the records the Final seeds itself from.
  - The conference/division map moved to `handball/league_structure.py` (`schedule_generator` re-exports it) — asking which conference a team is in should not import an OR-Tools solver.
  - Tested in `tests/test_playoffs.py` (Postgres, a whole bracket end to end) plus API authz/gating in `tests/test_api.py`; the pure seeding/pairing stays covered in `tests/test_postseason.py`.
- **Offseason free agency: sealed offers → RFA match → open auction** — the market, in `handball/free_agency_rules.py` (pure, DB-free, and it does not import sqlalchemy — a test asserts that) plus `handball/free_agency.py` (SQL) over alembic `0011`'s six tables. The commissioner opens a PERIOD; each ROUND takes sealed offers, then closes into per-player AUCTIONS: restricted players resolve by rights (own team led → stays; outside led → exclusive match window; declined → ordinary free agent with the offers already on the table), a sole offer signs itself, and two or more go to sequential bidding worst-initial-offer-first, where each turn is match / raise / forfeit. Last team standing signs at its own last offer; a full cycle with nobody raising goes to the commissioner. Rounds repeat until one draws no offers.
  - **Ranking** is one total order — salary, then term, then earliest submission (`fa_offers.id`, a bigserial, so it cannot tie the way a timestamp can). That tiebreak is what keeps MATCH and RAISE distinct: re-offering the leading contract ranks just below it.
  - **Exposure** (`check_exposure`) is the invariant the whole thing rests on: an offer is a promise, and a team may not promise more than it can keep. Bodies (one live offer per open roster spot), the hard cap, ONE mid-level exception shared across all outside offers, and — the case the sum alone misses — every offer must still be legal if it is the one that lands LAST, because the allowance falls off a cliff at each luxury threshold. A property test pins that an honourable board stays honourable as its offers convert.
  - **Offers are append-only**: an edit, a raise and a match all supersede rather than mutate, so the audit trail is honest and re-offering costs you your place in line.
  - **Concurrency**: lock order is period → round → auction → team → player, extending the team-then-player order `signing_service` already used. Managers take the round FOR SHARE and run in parallel; the commissioner's phase transitions take it FOR UPDATE and wait them out. Every path re-reads status after locking.
  - **Signings** all funnel through the extracted `signing_service.apply_signing`, so the pool deal and every auction award are the same write.
  - `POST /free-agency/{periods,offers,rounds/close,close}` and `/auctions/{id}/{bid,match,decline,force-forfeit,award}`, all behind `_require_owns_strict` (no commissioner bypass — in a sealed auction that would be a hole, not a convenience); `GET /free-agency/state` is the one document the page polls. Sealed offers are the only table not granted to `authenticated`: they are served through the API, which redacts per caller.
  - Tested in `tests/test_free_agency_rules.py` (68 pure) and `tests/test_free_agency.py` (Postgres, a whole period end to end), plus API authz/gating in `tests/test_api.py`.
- **The pool closes while the market is open** — `POST /signings` is refused during a period, and a new `season_readiness` check (`free_agency_open`) refuses to start period 1 until free agency is closed. Retiring a player voids their live auction in the same transaction, releasing every bidder's promise.

- **Free-agent signing** — `handball/signing_service.py`: picking a player out of the unsigned pool, always on the SAME fixed deal (`FREE_AGENT_CONTRACT_YEARS`/`SALARY` = 1 year, $0M), so the endpoint takes no term or value — the pool fills roster spots, it isn't a market. Offseason and in-season are one operation (a free agent is a non-retired player with no team, whenever that came about); the API refuses only while a period is simulating. Pure rules over a `SigningContext` snapshot (eligibility → roster room → money, in that order), SQL layer read-then-write, transaction locks team + player so concurrent signings serialize. A $0 deal never counts against the cap, but it still goes through `salary_cap.check_signing`: a team already above the hard cap on rookie deals may shed players, not add them. Contracts go on via `Player.update_contract`, the tested domain path. Roster limits bind (`max_roster`), because a player under contract cannot be dropped. `POST /signings`; Free Agents page in the web app. Tested pure in `tests/test_signing_rules.py`, over Postgres in `tests/test_signing_service.py` + `tests/test_api.py`. The pure layer stays general over term/value (and knows Bird rights via `players.rights_team_id`, stamped at expiry by `offseason._process_free_agency`, cleared on signing/retirement — alembic `0010`) because re-signing will price real contracts against exactly these rules.
- **Cap situation in the UI** — `GET /teams/{slug}/cap` (`signing_service.team_cap_report`) returns payroll, cap room, luxury-tax tiers, MLE, hard-cap headroom, roster room, and the two offer ceilings (own vs outside, `salary_cap.max_offer`), plus the league constants so the frontend labels thresholds without hardcoding them. Rendered as a one-line strip on the team page and as stat cards on the Free Agents page.
- **Shared lineup rebuild** — `handball/roster_layout.py` holds the canonical-arrangement rules (strongest healthy per position → starters → bench → reserves) that a trade and a signing both need. A trade applies them strictly (`rebuild_layout`: an unarrangeable roster rolls the trade back); a signing best-effort (`try_rebuild_layout`: mid-offseason a roster is legitimately incomplete and signing is the fix, so the new player just stays unplaced).

- **Salary-cap & contract rules foundation** — `handball/salary_cap.py` (constants in `simulation_vars.py`): contract limits (5 yr / $45M, $0 minimum), soft cap $150M, luxury thresholds $175M/$200M with $10M/$5M MLEs, $250M hard cap, Bird rights for own-player re-signings. Hard cap enforced at trade approval (`trade_service.approve_trade`); `Team.cap_situation` convenience added. Tested in `tests/test_salary_cap.py`.
- **Contract writes go through the rules** — `Player.update_contract` validates term/value via `salary_cap.validate_contract` and restarts `years_remaining`, so no write path can create an illegal deal. Rookie draft contracts are deliberately exempt from the *cap* (a team must be able to sign its picks); a team pushed over the hard cap that way is legal but blocked from starting the season. Because that state is legal, a team already over the cap may make payroll-*reducing* trades (`salary_cap.assert_trade_hard_cap`) — otherwise it could never get back into compliance.

Checks are pure functions of a `LeagueState` snapshot (`load_league_state` does all the reading), registered with `@readiness_check`, and every blocker is reported at once. Enforced on the first period of a season (`POST /periods/run`), reported by `GET /season/state`, rendered on the Commissioner page. Currently one check: no team above the hard cap. **To add another:** write a function, decorate it, add any new facts it needs to `LeagueState` + `load_league_state` — the API and UI need no changes.
